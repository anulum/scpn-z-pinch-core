# Threat model

Scoped to the current `computational_prototype` state. The executable
surface is the Python package `scpn_z_pinch_core` under `src/` (device
configuration, device geometry, diagnostic plan and plan envelope models
with their public JSON parsers, level-0 physics through the pinned SCPN
reactor kernel library and its optional native kernels, and the
tessellated and B-rep geometry tiers with STL, glTF and STEP exports) and the
validation tooling under `tools/`. The repository is public on GitHub and
its workflows run on hosted runners. The model is revisited whenever a new
surface (adapter implementation, solver seam, federation, release) is
added.

## Assets

| Asset | Why it matters |
|---|---|
| `reactor-domain.json` | source of project identity; downstream projects bind to it |
| `studio/portfolio-descriptor.json` | what the portfolio layer would ingest; must never overstate maturity |
| `capability-inventory.json` | public truthfulness of the implemented capabilities and their maturity |
| Public JSON parsers in `src/` | the only codec consumers use for configurations, geometries, plans and envelopes; accept untrusted bytes |
| Export writers (`write_stl`, `write_glb`, `write_step`) | write deterministic bytes to a path the calling code chooses; the package never chooses or derives a path from document content |
| `docs/CONTROL_ADAPTER_SPECIFICATION.md` | safety-relevant contract text (no-direct-actuation semantics) |
| Workflow definitions | hosted execution with a repository token |
| Licensing/provenance metadata | legal integrity of the repository |

## Trust boundaries and actors

- **Repository editor** (owner, reviewed contributor): trusted after review;
  every change passes the gate sequence.
- **Downstream consumer** (SPO, CONTROL, STUDIO tooling): trusts the
  manifest only as far as its digest and validator verdicts; must not be
  able to read more authority out of the metadata than the manifest grants.
- **Document producer** (any party that hands bytes to a public parser):
  untrusted; a parser either returns a fully validated object or raises the
  package's own error type.
- **Hosted CI**: untrusted-by-default execution environment; workflows
  carry empty top-level permissions, per-job least privilege, pinned action
  commit objects and bounded timeouts; the default workflow token is
  read-only.
- **Supply chain**: the hash-locked Python sets (`requirements-*.txt`,
  generated by `make lock` and installed with `--require-hashes`), the
  first-party kernel library pinned by commit and source-archive digest, and
  the pinned GitHub Actions are the only external code paths.

## Misuse paths and mitigations

| Misuse path | Mitigation |
|---|---|
| Editing the descriptor or inventory to imply implemented capability | both files are generated; `--check` drift gates in pre-commit, preflight, and CI fail on any manual edit |
| Adding a capability or claim without evidence | validator requires every capability to carry an allowed maturity and a committed evidence pointer, and keeps the claims inventory empty until a claims contract exists |
| Malformed or ambiguous document fed to a public parser | strict UTF-8 JSON; NaN and infinity literals rejected; the plan and envelope parsers also reject duplicate keys and non-canonical bytes; every field is validated before an object exists |
| Re-pinning the SPO registry silently | validator fails on version/digest mismatch against the manifest's recorded values (and against the portfolio map when present) |
| Treating review-only semantics or a Studio request as an actuator command | `spo_semantic_profile.actionable` is `false`; adapter specification defines no actuation verb; machine-protection statement is a required manifest field the validator enforces |
| Workflow tampering towards write authority | no write-authority or release workflow exists; permissions are empty at top level; `tools/audit_workflows.py` fails on any third-party action not pinned to a 40-hex commit and on drift from `.github/workflow-inventory.json` |
| Dependency substitution | exact version pins with sha256 digests for every locked distribution; the kernel library is pinned by commit and archive digest; dependency updates land only through the full gate sequence |
| Secret introduction | no secrets exist or are needed; GitHub secret scanning with push protection, the security-audit workflow and review gates scan the change |

## Fail-closed behaviour

Every validator in `tools/` exits non-zero on the first unrecoverable
finding, treats a missing file, unparseable JSON, duplicate JSON keys, or an
unknown schema as failure (never as "skip"), and prints the exact failing
check. The preflight orchestrator aggregates gate results and fails if any
gate fails or cannot run — a missing tool is a failed gate, not a pass.

## Residual risks

- The ecosystem cross-check against the portfolio map runs only where the
  canonical map file is present (the local canonical checkout); a standalone
  checkout validates manifest-internal truth only. Accepted: the map is not
  distributed with the repository by design.
- Licence-text files and generated JSON carry no in-file provenance header
  (format constraints); REUSE.toml annotations close this gap.
- No cryptographic signing of the manifest exists yet; digest pinning covers
  integrity of derivation, not authorship. Signing is a future portfolio
  decision.
