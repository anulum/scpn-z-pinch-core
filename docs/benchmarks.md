# Benchmarks

Every number here is regenerated by `benchmarks/level0_physics.py`,
`benchmarks/device_model_3d.py` or `benchmarks/device_model_cad.py` per the ecosystem benchmark standard (warm-up, repeated samples, percentiles, one
row per backend, provenance in the artefact). The operation is one pass
over a synthetic parameter grid evaluating, per point, the Bennett
equilibrium, the Kadomtsev criterion, the Shumlak-Hartman threshold and
the Pease-Braginskii current; the time is reported per grid point and
includes the Python call overhead of both backends (the native backend
is called per point through its binding, so this measures the
call-through cost of the kernels, not a vectorised scan). Nothing here is
a physics claim.

## Device 3D model tessellation — local workstation (non-isolated)

Artefact: `benchmarks/results/device_model_3d.local.json`
(schema `scpn-z-pinch-core.device-model-3d-benchmark.v1`, generated 2026-09-02T15:06:26.486456+00:00, at parent commit
`598fa4c2b40a` with the working tree of the landing commit).
Host: 11th Gen Intel(R) Core(TM) i5-11600K @ 3.90GHz, Linux-7.0.0-30-generic-x86_64-with-glibc2.39, Python 3.12.3;
load average at start 6.67 (other work was running on the host); cores not
isolated (shared workstation, so treat the numbers as indicative).
Operation: one full device tessellation (six bodies, 131072 faces at
4096 segments) followed by the signed volume and surface area of every
body; 3 warm-up passes, 20 timed passes; time per generated face.
Both backends are the pinned shared kernel library's
(`scpn-reactor-kernels`, ADR 0007). The Python floor row includes the
library's `TriangleMesh` validation (closure and orientation checks) that
every public build performs; the native row measures the library's native
kernels through their bindings (tessellation, volume, area) without that
validation, so the ratio compares a validated build against the raw kernel
cost.

| Backend | P50 µs/face | P95 µs/face | P99 µs/face | mean µs/face | throughput faces/s | status |
|---|---|---|---|---|---|---|
| `python_floor` (public API, always available) | 5.069 | 5.720 | 6.069 | 5.071 | 197283 | measured |
| `rust_native` (optional build of the pinned library: its `rust/`, maturin) | 0.197 | 0.249 | 0.249 | 0.189 | 5067089 | measured |

P50 speed-up of the native kernels over the validated Python floor:
25.7×. The fast row requires the optional native module and is never
the default.

## Device CAD model build, STEP export and faceting — local workstation (non-isolated)

Artefact: `benchmarks/results/device_model_cad.local.json`
(schema `scpn-z-pinch-core.device-model-cad-benchmark.v1`, generated 2026-09-03T09:29:18Z, at parent commit
`6df98b980b53` with the working tree of the landing commit).
Host: 11th Gen Intel(R) Core(TM) i5-11600K @ 3.90GHz, Linux-7.0.0-30-generic-x86_64-with-glibc2.39, Python 3.12.3;

isolated (shared workstation, so treat the numbers as indicative).
Back-end: the pinned third-party kernel (`cadquery` 2.8.0 on
OpenCASCADE 7.9.3.1), consumed through the shared library's `cad` group;
there is no Python-floor row because the CAD kernels have no bit-exact
floor by design (the library's ADR 0006). 2 warm-up runs, 10 timed runs;
time per operation.

| Operation | P50 ms | P95 ms | mean ms | throughput operations/s | status |
|---|---|---|---|---|---|
| `brep_build_and_manifest` (six bodies + assembly manifest) | 17.60 | 28.93 | 18.83 | 56.8 | measured |
| `step_export_normalised` (normalised STEP bytes) | 5.15 | 10.30 | 5.70 | 194.2 | measured |
| `facet_six_bodies` (closed meshes at the declared deflections) | 55.69 | 59.68 | 56.01 | 18.0 | measured |

The record build is dominated by the tier-G1 reference mesh (the
validated `TriangleMesh` construction of the comparison) and the
per-body evidence; nothing here is a physics or engineering claim.

## Fixed-runner (CI) number

Not yet published: the hosted `rust` job runs a benchmark smoke of the
physics and 3D benchmarks and the `cad` job a smoke of the CAD benchmark,
proving every backend measures, but the canonical fixed-runner artefact
requires a dispatchable benchmark workflow, which is held under the
current Actions cost policy. Until it exists, the only published numbers
are the local, non-isolated ones above.

## Regenerate

```bash
make rust
VIRTUAL_ENV=.venv PATH=.venv/bin:$PATH maturin develop --release -m rust/Cargo.toml
# the 3D-model benchmark needs the pinned library's native module; build it
# from the library checkout at the manifest's kernel_library.source_commit:
VIRTUAL_ENV=.venv PATH=.venv/bin:$PATH maturin develop --release -m <scpn-reactor-kernels>/rust/Cargo.toml
.venv/bin/python benchmarks/level0_physics.py --points 100000 --warmup 3 --repeats 20 --label local
.venv/bin/python benchmarks/device_model_3d.py --segments 4096 --warmup 3 --repeats 20 --label local
# the CAD benchmark needs the pinned library's `cad` extra (installed by
# the pinned dependency):
.venv/bin/python benchmarks/device_model_cad.py --warmup 2 --repeats 10 --label local
```
